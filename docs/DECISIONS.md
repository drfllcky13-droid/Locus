# Decisions

Record each design decision as: date, decision, reason, alternatives considered.

- **2026-09-22**: Stack is Tauri 2 + Rust core + React/TypeScript/Three.js UI. Reason: fast native math and file handling, quick UI iteration, one codebase for the main app and the portable viewer. Alternative: fully native C++/Qt (slower to build), Unity/Unreal (heavy, licensing).
- **2026-09-22**: No support for proprietary scanner or EDR formats without official vendor licensing. Reason: clean-room requirement and legal risk. Users import E57 and CSV instead.
- **2026-09-22**: TypeScript pinned to 6.x. Reason: typescript-eslint 8 refuses to run on TS 7. Alternative: drop type-aware linting (loses checks). Revisit when typescript-eslint supports TS 7.
- **2026-09-22**: `locus-validate` exits non-zero until it has real scenarios. Reason: an empty validation run must never read as a pass.
- **2026-09-22**: Bundle identifier `app.locus.desktop` is a placeholder until a publisher domain is chosen; it must be fixed before the first signed release (Phase 14), since changing it moves the app-data folder.
- **2026-09-22**: The 3D viewport renders on demand (camera change or resize), not in a continuous loop. Reason: idle GPU and battery use on field laptops. Animation playback (Phase 9) will run its own loop while playing.
- **2026-09-22**: The on-demand viewport must also redraw when point cloud chunks finish loading (Phase 2), and whenever anything else changes the scene without moving the camera. Reason: redraws currently only fire on camera change or resize, so a newly loaded chunk would stay invisible until the user moves the view. Phase 2 must expose one `requestRender()` that loaders call.
- **2026-09-22**: Large test fixtures (for example the 100M-point E57 memory test) are generated by a fixture script at test time, never committed. Reason: keeps the repo small, and the generator is itself reviewable evidence of what the test data contains.
- **2026-09-22**: No explicit "Save". Every change to `project.sqlite` is its own committed transaction, and the audit entry is written in the same transaction. Reason: a crash can never leave analysis state and audit log out of step, and nothing unsaved can be lost. Alternative considered: an in-memory model with explicit save, which makes it possible to act without a matching log entry.
- **2026-09-22**: The audit chain head is mirrored into the `meta` table on every append and checked on open. Reason: a hash chain alone can't detect rows deleted from its tail. Limitation: someone who rewrites both the log and `meta` consistently is not detected by a self-contained file; external anchoring (hash in the report, signed exports) is the answer and is documented in `docs/methods/audit-log.md`.
- **2026-09-22**: Import is two steps, preview then commit. Preview reads the source read-only and shows hash and counts. Commit copies the file, and refuses if the copy's hash differs from the preview hash. Reason: the examiner sees and confirms the hash before anything enters the project, and a file that changes between preview and commit is caught.
- **2026-09-22**: Formats that declare no unit (PLY, PTS, XYZ, OBJ, and LAS without a CRS) require the examiner to pick the unit at import; there is no silent default. The choice is audit-logged. Reason: a wrong unit silently scales every measurement (for example US survey feet vs meters).
- **2026-09-22**: Importing a file whose SHA-256 already exists in the project is refused, and the refusal names the existing record. Reason: two evidence records for the same bytes would make the evidence list ambiguous.
- **2026-09-22**: Unicode-3.0 is allowed provisionally in `deny.toml` (it enters through Tauri's url/idna crates). It is permissive but not on the CLAUDE.md allowlist; pending Addison's OK.
- **2026-09-22** *(superseded by the next entry)*: Locus is desktop-only and fully offline (CLAUDE.md rule 8). No network requests of any kind: no telemetry, update checks, online license activation or CDN assets; all fonts, libraries and assets are bundled. Phase 14 changed to match: updates ship as signed packages the user installs manually, and crash reporting became local crash logs the user can choose to send. GitHub Pages and any other hosting must never be enabled on the repo. Reason: case data must never leave the examiner's machine, and the app must run on air-gapped forensic workstations. Alternative considered: an opt-in updater, rejected because any network path has to be justified in court and audited.
- **2026-09-22**: Supersedes the offline-only entry above. CLAUDE.md rule 8 is now "Desktop only": Locus ships as an installed desktop app, with no web version and no hosted deployment, and nothing in the repo may be set up to publish it as a website (no GitHub Pages or other hosting). Network features such as auto-update are allowed, so Phase 14 is back to its original wording (auto-update with signed builds, crash reporting that never uploads case data). Reason: Addison's clarification; the concern is web deployment, not network access.
- **2026-09-22**: E57 points are decoded by Locus from the `e57` crate's raw record reader, not its "simple" reader. Reason: the simple reader (e57 0.11.13) returns "Cannot read next point because of logic error" when a scan's final data packet is short (reproduced with a 3-point scan that has a bit-packed invalid-state field); the raw reader reads the same file correctly. Decoding ourselves (scaled-integer scale/offset, spherical to Cartesian, invalid-state handling) also keeps every conversion in code we test. Worth reporting upstream.
- **2026-09-22**: LAS unit detection: the unit comes from GeoTIFF keys 3076/4099 or the WKT axis units (ellipsoid, parameter and base-CRS units are ignored). WKT factors match a known unit within 1e-8 relative, because files often truncate the US survey foot (0.304800609601219). Horizontal-only units are accepted with a warning that heights are assumed to share the unit. Mixed horizontal/vertical units and geographic (degree) coordinates are refused. A CRS named without a unit (e.g. only an EPSG code) makes the examiner choose, since resolving EPSG codes needs a database Locus doesn't bundle yet.
- **2026-09-22**: OBJ and glTF files reference companions (.mtl, textures, .bin). Only the selected file becomes evidence; referenced files are listed as import warnings so the examiner can import them too (or use a self-contained .glb). glTF is stored as declared (meters, Y-up, `y_up` flag); conversion to the Z-up project frame happens at placement (Phase 5), not by altering source data.
- **2026-09-22**: Unicode-3.0 approved by Addison and added to the CLAUDE.md rule 7 allowlist and `deny.toml`.
- **2026-09-22**: Octrees are per scan, in scan-local coordinates converted to meters, with the pose applied at draw and pick time. Reason: registration (Phase 3) then only changes a matrix, never a multi-gigabyte rebuild. Nodes store f64 positions and u32 source record numbers (33 bytes per point on disk) so picks resolve to exact stored coordinates and cleanup can refer to source records independently of the octree layout.
- **2026-09-22**: Every point lives in exactly one node (top-down 128³ grid sampling, Potree 1 style), not duplicated across LOD levels. Reason: a pick or cleanup refers to one stored point unambiguously, and full resolution in a region is the union of the nodes on the path to its leaves (used by cursor-focused refinement).
- **2026-09-22**: GPU picking only identifies a point (node slot, index); coordinates are resolved in Rust from stored f64 data, and measurement commands re-resolve every pick server-side (item 6). The client's own coordinates are never used for a measurement.
- **2026-09-22**: Measurement uncertainty assumes independent, isotropic per-point σ, a project setting defaulting to 2 mm, shown with every result. Reason: rule 4 requires an uncertainty; scanner range noise is the dominant term for picked points, and the examiner can set it from the instrument's specification. See docs/methods/measurement.md.
- **2026-09-22**: Colour pipeline in the viewer: point shaders decode sRGB to linear, the EDL target is linear half-float, the composite encodes once, and the background is written directly. Found while testing: an sRGB render target double-encoded (three.js encodes in the shader and the hardware encodes again), which washed colours out like the spike did.
- **2026-09-22**: GLSL 3 ShaderMaterials declare their own fragment output (`layout(location = 0) out vec4 fragColor`); three.js r186 no longer aliases gl_FragColor for them. Shader compile errors only show at run time, so they are checked by running the app (see docs/phase2-report.md), not by unit tests.
- **2026-09-22**: NvOptimusEnablement and AmdPowerXpressRequestHighPerformance are exported from locus.exe as requested (item 7), but WebGL renders in WebView2's own GPU process, which those exports don't reach. The window also passes `--force_high_performance_gpu` to WebView2, and Help → About shows the GPU WebGL actually uses so the examiner can check. On a hybrid-graphics laptop Windows' per-app graphics setting is the remaining lever; this has not been tested on such a laptop (none available).
- **2026-09-22**: Adaptive budget: starts at 10M points, shrinks 3 % per frame while the average frame time is above 28 ms, grows 2 % per frame while below 16 ms and the budget is what limits detail, between 1M and 30M points.
- **2026-09-22**: Lasso delete defaults to "visible surface only" (3 px cells, tolerance 2 cm + 0.5 % of depth), with "all depths" as an option. Both modes skip points hidden by the clip box or plane, and the examiner sees both counts before confirming. The depth test runs on full-resolution data in Rust, so it is reproducible from the stored parameters and doesn't depend on what the GPU drew. See docs/methods/cleanup.md.
- **2026-09-22**: Picks the 32-bit pick encoding can't represent safely (more than 4,094 nodes loaded, or a node index beyond 20 bits) are refused with a message, never resolved to a possibly wrong point.
- **2026-09-22**: Deferred: parallelising statistical outlier removal (tiles are independent, so rayon over tiles is the obvious route). It is single-threaded today, taking seconds per 10M points. Revisit when a real case needs it on a very large scan.
- **2026-09-22**: Synthetic scene generation moves from `locus-validate` into a library crate, `locus-synth`, and `locus-validate` keeps the CLI. Reason: registration tests need ground-truth scans in memory, and a test-only dependency on the validation binary would become a cycle once `locus-validate` runs the registration pipeline end to end (Phase 13).
- **2026-09-22**: Ground truth for registration is a JSON sidecar written next to each synthetic E57 (`<file>.truth.json`): the true scan poses, the target geometry and any injected faults. The E57 itself carries the true pose, no pose, or a perturbed pose, chosen per run, because real exports arrive in all three states. Registration accuracy is judged on poses relative to the first scan, since the world frame of an unregistered project is arbitrary.
- **2026-09-22**: Registration math uses nalgebra (Apache-2.0) for decompositions and small dense solves, kiddo for neighbour queries and rayon for per-point work such as normals. Reason: well-tested linear algebra instead of hand-rolled SVD and eigen solvers; all on the licence allowlist.
- **2026-09-22**: Sphere centres are reported from a fit with the radius held at the nominal target radius; a free-radius fit is only a check (within 3 mm). Reason: a scanner sees at most half a sphere, and a free radius correlates with the centre along the line of sight.
- **2026-09-22**: Checkerboard centres are only as precise as the point spacing across the board allows (each edge sample can sit anywhere between two points). The reported covariance keeps a floor of spacing/√12 per sample and counts only half the samples as independent, so it never claims more than the data supports. Registration weights each target by that covariance.
- **2026-09-22**: The CI viewer smoke test runs the built frontend in headless Chromium (Playwright, Apache-2.0) with software WebGL, with the Tauri IPC and `locus://` protocol answered from a small recorded fixture (`tools/smoke/fixture`, 2 MB, re-recorded by `capture.mjs`). Reason: the real app can't be driven on CI. Tauri uses WebKitGTK on Linux, which has no DevTools port, and on the Windows runner WebView2 started with the app's own browser arguments and never opened the debugging port. The full-app WebView2 test stays as a manual pre-release step. The fixture is committed, an exception to the generate-at-test-time rule, because recording it needs a built app and a desktop session.
- **2026-09-22**: A pre-push git hook (`.githooks/pre-push`, enabled by `sh tools/setup.sh`) runs `cargo fmt --check` and `cargo clippy -D warnings`, so lint failures are caught before CI.
- **2026-09-22**: Coarse cloud-to-cloud registration assumes levelled scans. The spec named FPFH + RANSAC; FPFH features are kept, but consensus comes from voting over headings and translations, not 3-point RANSAC. Reason: on the synthetic room (planar surfaces, a regular pillar grid) only 0.2–0.5 % of feature matches between two stations are correct, too few for 3-point RANSAC to ever sample three good ones. With levelled scans (tilt compensators hold z to a fraction of a degree), a single pair fixes the translation for each heading, and a few correct pairs stand out. Candidates are chosen by a score, not by vote count: overlap of wall-like surfaces minus visibility conflicts (points placed where the other scanner saw through empty space). Repeated structure, which fooled vote counts (a pose shifted by one pillar spacing), fails the visibility test. A near-tie between clearly different poses is reported as ambiguous. Scans that aren't levelled need a starting pose from targets or the file; the untested RANSAC path was removed rather than shipped.
- **2026-09-22**: ICP covariance is reported as the formal `σ²(JᵀWJ)⁻¹`, documented as a lower bound (dense neighbouring points aren't independent, and systematic effects aren't modelled). The pose graph (step 3) must not treat it as a realistic uncertainty without inflating it. ICP also reports conditioning (weakest constrained direction as a share of pairs) so corridors and other sliding geometry are flagged.
- **2026-09-22**: Registration uses a scan's rough pose (the scanner's on-site pre-registration, or the pose in the file) when there is one: the coarse cloud-to-cloud search then looks only within 10° and 2 m of it. Without targets or a rough pose, a cloud link rests on shape alone and is marked `shape_only` for the examiner to confirm. Reason: the end-to-end test on a nearly symmetric room placed two scans flipped 180°, consistently across every link that touched them, so every link passed the χ² test. A consistent error like that can't be detected from the links, so it has to be prevented (prior) or disclosed (mark). The acceptance test uses rough poses off by 0.5 m and 5°, and a separate test checks that without them, any wrongly placed scan is only connected by marked or flagged links.
- **2026-09-22**: The synthetic room's spheres moved from 6 to 20, spread irregularly between the pillar rows. Reason: with 6, stations 12–18 m apart shared at most 2 detectable targets, so target links never formed. A regular grid would make target matching ambiguous; real targets are placed irregularly.
- **2026-09-22**: Slow synthetic-scan tests (millions of points) are `#[ignore]`d in the normal test run and run in their own CI job (`registration`, release build, Linux), in parallel with the main job.
- **2026-09-22**: Reports are rendered with Typst 0.15, compiled in-process (`locus-report`), as the spec planned. Approved by Addison, with a data-file exception added to CLAUDE.md rule 7: CC-BY-4.0, CC-BY-SA-3.0, LPPL and the W3C licence are allowed only for data files bundled unmodified (hyphenation patterns, citation styles, character tables), never for code. Reason: Typst always embeds such data (hayagriva's CSL citation-style archive, hypher's hyphenation patterns, typst-assets' HTML/MathML tables, two-face's syntax definitions) and has no feature flags to leave it out; the embedded data is unmodified and not code. Trimming was checked: `typst` exposes no features, `typst-library` uses hayagriva's style archive directly and pulls hypher with every language, so dropping any of it would mean patching Typst. The one easy trim is taken: Typst's bundled fonts (OFL, GUST, GPL-with-font-exception, Bitstream Vera) are not used. Reports use the Go fonts (BSD-3-Clause, the licence embedded in the font files themselves, Bigelow & Holmes), shipped in `crates/locus-report/fonts/`. The build-time crate `ar_archive_writer` (Apache-2.0 WITH LLVM-exception) gets the same deny.toml exception as `target-lexicon`. Every bundled third-party data file is listed with its licence and attribution in THIRD_PARTY_NOTICES.txt, shipped with the app and shown from Help → About, and CI fails if embedded data appears without an entry.
- **2026-09-22**: Report rendering is sealed: a hand-written Typst `World` with one template, one `data.json`, no file access, no packages and no clock (dates come in the data). Missing fonts or glyphs, which Typst treats as warnings, are errors, so text can't silently vanish. All numbers are formatted in Rust before the template sees them, and tests check the laid-out text against the adjustment's own figures. Exporting a report writes an audit entry with the PDF's path and SHA-256.
- **2026-09-22**: Option C for the data Typst bundles (Addison). Accepted as data under CLAUDE.md rule 7's exception: the FSF all-permissive licence (English and Norwegian hyphenation), the custom Bulgarian and Sanskrit pattern licences, and the Sublime HQ packages licence (two-face syntax definitions). The exception now also covers data converted to another format without changing its content (hyphenation patterns compiled into tries, CSL styles into CBOR, tables into generated Rust). Removed: Slovak hyphenation patterns (GPL-2.0-or-later only) and Hungarian (MPL-1.1 OR GPL-2.0 OR LGPL-2.1), by patching hypher 0.1.8 via `[patch.crates-io]` to a copy in `patches/hypher/` with 6 lines and 2 files removed (`tries/sk.bin`, `tries/hu.bin`, the two languages in the `full` feature, and their `include_bytes!` arms). Reports can't hyphenate Slovak or Hungarian text; they are English. The patch directory is excluded from the workspace so it isn't linted or tested as ours. **When Typst updates hypher:** follow `patches/hypher/PATCH.md` (copy the new version, repeat the three edits, update the patch entry); `tools/notices/notices.py check --strict` in CI fails if either pattern file exists in the hypher being built, is embedded, or its feature is on, so an unpatched update can't slip through.
- **2026-09-23**: CI split for speed (target under 15 minutes per push), approved by Addison. Tests run with cargo-nextest. Heavy tests (the synthetic-scan registration tests and the 100M-point E57 import) are named `heavy_*`, `#[ignore = "heavy: …"]`, and form the nextest test group `heavy` (`.config/nextest.toml`, one at a time). Per push: lint (fmt, clippy, notices, frontend checks) on Linux, the fast tests on Windows and Linux, the heavy tests and the app build with the viewer smoke test on Linux. Nightly, on demand and for `v*` tags: the heavy tests, the app build and clippy on Windows too. The dev profile now optimises only the numeric crates (locus-register, locus-synth, kiddo, nalgebra, laz) and drops debug info for dependencies. Optimising every dependency had made a cold Windows test build take 48 minutes; the fast tests still finish in seconds.
- **2026-09-23**: The notices check separates our own embedded files from ignores. `first_party` lists them (Typst templates, the notices file itself, the symbol library) with the licence `LicenseRef-Locus-Proprietary`; they are not third-party and are not listed in the notices. Every `ignored` entry must be explained: either `unless_feature` (the check fails if that feature is on) or `test_only`, naming the dependency's source file whose `#[cfg(test)]`/`#[test]` code includes it, which the check verifies. An ignore that matches nothing the scan finds is also an error, so a stale entry can't later hide a new file.
- **2026-09-23**: Road broken-line patterns are a per-road setting (painted length, gap), defaulting to 3 m / 9 m. Reason: marking standards vary by jurisdiction, and a drawing should show the pattern actually on the road.
- **2026-09-23**: 3D scenes are stored exactly like diagrams (immutable revisions with SHA-256 and an audit entry each). Schema 5 adds `scenes` and `scene_revisions`; the storage code is shared (`locus-core/src/document.rs`), and a revision's id field is now `document_id` for both kinds. An extrusion or roof names the diagram revision (id and hash) it was built from and is not rebuilt when the diagram changes, so the 3D shown is always traceable to one saved plan.
- **2026-09-23**: Extrusion reuses the plan's own geometry functions (`walls`, `roadLines`) instead of rebuilding walls or roads in 3D code. Reason: the 2D–3D alignment criterion (1 mm) then holds by construction. Tests measure it at 1e-9 m.
- **2026-09-23**: Shed, gable and hip roofs are built for rectangular rooms only; other outlines get a flat roof. A hip roof on an arbitrary polygon needs a straight skeleton, which is deferred until a case needs it.
- **2026-09-23**: Library models are generated from their dimensions in code (`scene3d/library.ts`), not drawn as mesh files: nothing to copy or license, every size is editable, and tests check each model's bounding box against its parameters. The shapes are deliberately generic (no makes, brands or likenesses).
- **2026-09-23**: Snapping a model fits a plane to the cloud's visible points within a radius of the pick (default 0.1 m, at least 10 points), reusing the measurement plane fit, and stores the fit's residual with the model. The normal is taken facing the camera. Placement is otherwise the examiner's: typed values or the gizmo.
- **2026-09-23**: The sun's position uses the NOAA solar position algorithm in `locus-analysis` (stated accuracy one arcminute, 1800–2100), not NREL SPA. Reason: SPA's extra precision (0.0003°) matters for solar engineering, not for scene lighting, and NOAA's algorithm is short enough to verify by hand. The project frame's true north is a per-scene setting, because a project frame from scans need not have +y north.
- **2026-09-23**: The heavy group runs as three parallel jobs per OS: the hybrid registration acceptance test, the injected-bad-link test, and the rest (the third acceptance test, the registration unit tests on synthetic scans and the 100M-point E57 import). Reason: each registration acceptance test takes about ten minutes on a four-core runner, and the old single `registration` job took 44 minutes. The three share one release-build cache.
- **2026-09-23**: Ground-truth generators for the Phase 6 tools live in `locus-synth` (library) with commands in `locus-validate` (`gen-trajectory`, `gen-bloodstain`, `gen-camera`), following the scan generator's split. Each writes `truth.json` (options, truth and simulated measurements), `scene.e57` and any images. The camera generator renders a distortion-free pinhole image and resamples it through the inverse lens distortion (Newton's method), because distorting triangle corners alone leaves straight edges where a real lens curves them.
- **2026-09-23**: Analysis runs are one generic, immutable record type (schema 6, `analyses`): tool, method version, the run as JSON (inputs as resolved from stored data, parameters, results with uncertainty, assumptions, limitations), its SHA-256, and the run it revises. A run can be withdrawn with a logged reason, never edited or deleted. Each tool defines its run type in `locus-analysis`; the report is rebuilt from the stored record, so it can be reprinted at any time and prints exactly what was stored.
- **2026-09-23**: All analysis reports share one Typst layout (`templates/analysis.typ`): the record's identity (id, method, hash, who and when, audit head), a warnings box, then sections of text, pairs, tables, lists and simple figures. Each tool only fills in the sections, so the other tools can't drift from the pattern.
- **2026-09-23**: Trajectory uncertainty is first-order propagation from every picked coordinate, checked against the fit's own residuals (χ²; the covariance is inflated by the Birge ratio when they scatter more than stated), plus any rod play in quadrature. It is reported as a 95 % cone from χ²₂. The drawn cone for muzzle positions is a separate, examiner-set half-angle (default 5°), and the report warns when the fit's cone is wider.
- **2026-09-23**: Picking prefers the nearest surface. Among the points drawn in the pick window, candidates within 1 cm + 2 % of the nearest candidate's depth count as that surface, and the one nearest the cursor is picked. Reason: close up, point sprites (at most 8 px) leave gaps, and the old rule (the pixel nearest the cursor) could pick a farther surface seen through them. The trajectory check in the app found it: a pick on a panel's back face returned the wall behind it.
- **2026-09-23**: The nearest-surface picking change (above) affects only which point a new click selects. Saved measurements and analyses store the coordinates resolved when they were made and are never recomputed, so records made before the change keep their values. A test reads a stored measurement back after reopening the project and compares it exactly. That test found that `locus-core` parsed stored JSON without exact float round trips, so a coordinate could come back one bit off (about 1e-11 m). serde_json's `float_roundtrip` is now on, and stored values read back bit for bit. A regression test reproduces the case found in the app: a click in a gap between a close panel's 8 px sprites, with a wall showing through.
- **2026-09-23**: Hole centres are fitted from the rim (largest empty circle near the click, one rim point per spacing-sized sector, Levenberg–Marquardt ellipse), and the fit's centre σ replaces a stated σ. Axes are reduced by half the point spacing and carry the quantisation error spacing/√12, like the checkerboard targets. A manual centre (the clicked point) is allowed only with a reason, stored and printed. The ellipse's impact angle is reported as an independent cross-check and never changes the path. Agreement is tested on the axis ratio b/a against sin(path impact), not on angles, because asin skews the errors badly for near-round holes. The in-app check found this: an angle test flagged a 78° hole whose ratio was 1.6σ from expected.
- **2026-09-23**: Trajectory angle conventions are a per-run parameter, printed in the report's method section: surface angles either "level and perpendicular" (vertical from level; horizontal left or right of perpendicular, viewed facing the surface; default) or from the surface normal; the bearing from project +y or a named axis at a stated angle from it. Both cones are kept and named in the UI, figures and report as "Measurement uncertainty (95 %, computed)" (blue) and "Examiner-defined zone (±X°, analyst judgment)" (orange). The case number is a project setting, printed on every analysis report.
- **2026-09-23**: The bloodstain origin is fitted in angle space: the point whose straight paths to the stains best match each stain's measured impact angle and direction, in units of their 1σ (Levenberg–Marquardt from the plain least-squares point nearest the paths). The spec's "least-squares point minimizing summed squared distance to all rays" is the starting point, not the result. Reason: a direction error θ makes a stain's path miss the true origin on one side only, by d sin α cos α (1 − cos θ); near-round stains have direction errors of tens of degrees; with realistic noise the perpendicular-distance point (weighted or not) was 12–32 cm off with its region covering the truth 0–82 % of the time. Per-stain residuals are still reported as distances, and in σ units.
- **2026-09-23**: Bloodstain stains are used only when clearly moving upward: a wall stain whose direction is within 90° − 2σ of straight up. Floor, downward and uncertain stains are left out unless the examiner includes them with a reason (stored, printed, warned). Reason: with hand-measurement noise, 14 % of stains whose measured direction pointed up were really moving down, and pulled the origin about 20 cm low, which resampling cannot see; with the 2σ rule the 95 % region covered the truth 95 % of the time. The analyst's "upward" mark is the tail they click; the rule applies it with its uncertainty.
- **2026-09-23**: The bloodstain 95 % region is a bootstrap ellipsoid with Hotelling's T² radius, p n/(n − p) · F(p, n − p) for p = 3, not χ²₃: the covariance is estimated from the same stains. With 30 stains χ² covered the truth 88 % of the time, T² 94.5 %. At least 4 stains are required.
- **2026-09-23**: Stain photos are decoded by the webview (JPEG, PNG) and a greyscale crop is sent to the Rust edge finder, instead of adding a JPEG decoder crate. The edge points, seed and threshold are stored with the run and the ellipse is fitted in Rust from them, so the record is reproducible without the decoder. The photo's bytes are fetched through the existing hash-checked evidence command.
- **2026-09-23**: A stain's surface normal is taken on the side the examiner viewed it from when picking its alignment pairs, and that viewpoint is kept with the stain. The in-app check found why: using the view at save time put the camera outside the room, flipped two walls' normals and mirrored their photos.
- **2026-09-23**: A stain's direction uncertainty includes its photo's rotation on the surface, σ_point / √Σ|p − p̄|² from the scan points' 1σ and the pairs' spread (checked by Monte Carlo); the automatic edge's systematic error (0.2 % per axis, 0.1° on orientation, measured on the generator's photos) is added to the ellipse fit's own covariance.
- **2026-09-23**: Analysis overlays in the 3D view are keyed by tool, so the trajectory and bloodstain panels can each show theirs. locus-analysis builds optimised in the dev profile (its bootstrap and Monte Carlo tests), and the two slow bloodstain validations (1,700 rendered photos; ballistic flight) are in the heavy test group.
- **2026-09-23**: CI is sized for GitHub's free plan (2,000 private-repo minutes a month; Windows minutes count double), which the project stays on. Pushes and pull requests run Linux only (lint, licences, fast tests, app build and viewer smoke test), and skip changes to docs alone. Windows and the heavy tests run on demand (workflow_dispatch) and for release tags; the nightly run is dropped. Reason: the nightly Windows heavy runs and per-push Windows jobs used up the month's minutes and GitHub stopped starting jobs. The heavy tests are run locally before pushing changes to the code they cover.
- **2026-09-23**: The bloodstain origin stays the fit in angles (approved).
